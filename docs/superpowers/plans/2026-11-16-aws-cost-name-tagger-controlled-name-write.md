# AWS Cost Name Tagger — Controlled Name Write Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended by the skill) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **User instruction overrides any automatic review chain:** execute only the tasks explicitly authorized by the Human Owner; do not trigger repeated independent reviews or a following task automatically.

**Goal:** Produce reliable Name approvals for all 18 existing AWS resource kinds, and—only after separate policy and execution approvals—apply an approved Name to a safe target and verify it by AWS Readback.

**Architecture:** Reuse the existing CUR/metadata `plan()` and `Investigator.resolve()` without weakening their read-only behavior. Add distinct modules for canonical Owner-signed approvals, scope/side-effect validation, a durable single-host one-shot Intent ledger, a mockable executor and opt-in service adapters. Deliver a completely offline, fail-closed vertical slice first; any real AWS write path is a separate, explicitly authorized phase.

**Tech Stack:** Python >=3.10, `unittest`, `sqlite3`/`fcntl`/standard library, pinned `boto3[crt]==1.43.116` from `pyproject.toml`, OpenSSH `ssh-keygen -Y` for detached signatures, Ubuntu Linux secure filesystem assumptions, `uv` locked dependencies. No additional cloud services or Broker.

**Spec:** `docs/superpowers/specs/2026-11-16-aws-cost-name-tagger-controlled-name-write-design.md` at `yohi/aws-cost-name-tagger` commit `4129cffa1f3d0e02be47cfc5649d0e7d019e71ea` (Design R0.2.1). This plan is **proposed, not an adopted Design or AWS write authorization**.

## Global Constraints

- **Current authority:** `G1_NOT_PROVEN / G2_NOT_VERIFIED / SAFETY_HOLD_ACTIVE / AWS_WRITE_BLOCKED`. The Owner has not adopted R0.2.1, authorized Trust Anchor enrollment, approved a normative exception, or granted real AWS access. These are distinct future decisions.
- **Execution stop:** Until the Human Owner explicitly approves a subsequent implementation scope, *do not implement this plan*. In any authorized offline implementation, do not call live AWS APIs, change IAM, remove the Safety Hold, or accept an environment variable/CLI flag as a way around it.
- **Name semantics:** Only `ABSENT` or exactly `EMPTY` may be candidates; whitespace is `NONEMPTY`; `UNKNOWN`, duplicate/case-variant Name, truncated tag pages and malformed responses are blocked. Treat S3 as a candidate kind but never automatically enable its write adapter.
- **Granularity:** One verified Name approval, then a **separate** execution authorization for exactly one canonical ARN, one exact Name and one AWS operation. No batch grant while INV-N05 remains authoritative. `run --mode y` remains review-only; `apply()` and `Investigator.write_name()` remain hard blocked.
- **Signatures:** Name and execution are separate OpenSSH namespaces: `aws-cost-name-tagger-name-approval-v1` and `aws-cost-name-tagger-execution-v1`. Only canonical `payload` is signed; `approval_id` / `authorization_id` = lowercase SHA-256 of canonical payload bytes; `signature_ref` stays in the envelope. No CSV, raw digest, STS principal, Git author, or user-provided public key substitutes for an enrolled Owner Trust Anchor.
- **HOLD:** An untrusted/missing Trust Anchor is `BLOCKED_OWNER_AUTHN`. Writer-control evidence **and** IAM/ABAC/automation side-effect analysis (INV-N09) are independent requirements. Unverified or unsupported adapters remain blocked.
- **Ledger:** Single Ubuntu host, one trusted writer UID, strict cross-process lock and durable records. Old/incomplete Intents, replayed approvals/nonces, scope HOLD, corrupted/missing ledger and unproven scope mapping fail closed. In-memory `ALLOW_FIRST_SEND` is not a persistent capability. `SEND_ATTEMPT_CONSUMED` is durable *before* calling an AWS mutation method; crashing after consumption never restores send authority.
- **Failures:** On `OUTCOME_UNKNOWN` stop the current run (INV-N07), never retry a mutation or auto-rollback. Readback mismatch is `WRITER_CONTROL_SUSPECTED`, not proof of a competing writer; persist a scope HOLD. If HOLD persistence fails, block the host.
- **No new review loop:** Run the stated task tests and a single bounded self-check; record unresolved findings with evidence. Once the approved scope is complete, stop at the Human Owner checkpoint.

## Review Focus (five practical failure classes; each pinned to a task test)

1. Unpaired Unicode surrogate, floats, duplicate/unknown JSON keys and noncanonical signer input → **reject**, not a different digest (Task 1 `test_reject_noncanonical_payload`).
2. Edited Name reusing a prior approval, or a `proposal_id` in place of an execution ID → **reject** (Tasks 1–2 `test_edited_name_invalidates_old_signature`).
3. Scope writer control appears valid but an IAM/ABAC/EventBridge/IaC side-effect dependency is unavailable → **BLOCKED_SIDE_EFFECT_UNASSESSED** (Task 3 `test_side_effect_unknown_blocks`).
4. Crash after `SEND_ATTEMPT_CONSUMED` but before the SDK call, followed by a same-PID/same-ID restarted process → **no send** (Task 4 `test_consumed_crash_never_reopens`).
5. SDK timeout/readback mismatch, including stale/malformed Name response and unsafe tag-set replacement APIs → **no retry**, correct HOLD, no `APPLIED_VERIFIED` (Tasks 5–6 `test_mismatch_holds_scope` and `test_set_replacement_unsupported`).

## Phase A — Offline-only deliverables (eligible for *future separately approved* implementation)

### Task 1: Canonical, authenticated approval contract

**Files:** Create `name_tag_approval.py`, `test_name_tag_approval.py`.

**Interfaces:**
- Produces `canonical_payload(payload: Mapping[str, object], *, kind: Literal["name", "execution"]) -> bytes`, `approval_digest(canonical_bytes: bytes) -> str`.
- Produces `verify_envelope(raw_envelope_json: bytes, *, kind: Literal["name", "execution"], trust: OwnerTrust, now_utc: datetime) -> VerifiedEnvelope`, `revalidate_verified_envelope(verified: VerifiedEnvelope, *, kind: Literal["name", "execution"], trust: OwnerTrust, now_utc: datetime) -> VerifiedEnvelope`, and `ApprovalRejected(code: str)`. `VerifiedEnvelope` has immutable `kind`, `raw_envelope_bytes` (defensive copy of the signed JSON), `canonical_payload_bytes`, `content_id`, recursively immutable `payload`, `owner_principal_id`, and immutable `signature_ref`.
- `OwnerTrust` is constructed exclusively from a pinned, protected `allowed_signers` file and enrolled Owner ID/fingerprint/allowed role mapping; the executing user must not choose or write its trusted keys.
- For the supported canonical subset, only fixed ASCII field names, JSON string, `null`, boolean and *integer* fields (such as `schema_version=1`) are allowed. Reject floats, unpaired surrogates, unknown or duplicate keys and mixed types. Implement RFC 8785-compatible UTF-8 canonicalization for that constrained schema, with fixed-byte fixture vectors; never relabel unrestricted `json.dumps(sort_keys=True)` as complete RFC 8785.
- **F006 — untrusted input and immutable verifier output:** The authenticated ingress is **raw UTF-8 JSON bytes**, not a pre-parsed `Mapping`. Strictly decode/parse with `object_pairs_hook` (or equivalent) rejecting duplicate keys at every nesting level *before* conversion to a mapping, reject invalid Unicode/JSON/nonfinite numbers, then enforce closed fields/types and canonicalize. Derive `content_id = SHA256(canonical_payload_bytes)` and verify this digest and the OpenSSH signature over the **same bytes**, using the pre-enrolled namespace, Owner ID/role, key and current expiry/revocation constraints. Construct `VerifiedEnvelope` with deep-frozen copied payload and raw/canonical bytes; retain no mutable alias to a caller buffer/Mapping. `revalidate_verified_envelope` does **not** trust a Python type, `isinstance`, copied object or user-provided digest: it re-parses `raw_envelope_bytes`, re-verifies the Owner signature with protected trust data and compares the freshly verified kind/Owner/canonical bytes/content ID/deep payload to the supplied snapshot before returning a newly authenticated immutable result. Any mismatch is `BLOCKED_OWNER_AUTHN`; it cannot produce an execution capability.

### Task 4: Crash-safe single-host Intent and scope HOLD ledger

**Files:** Create `name_tag_ledger.py`, `test_name_tag_ledger.py`. Consume Task 1 `OwnerTrust` and Task 3 `ScopeEvidence` / `SideEffectEvidence`. No Broker or external persistence.

**Interfaces (F005):**
- `ScopeAction = Literal["INITIALIZE", "RELEASE"]`. `VerifiedScopeDecision` is a verifier-created, immutable proof with `action: ScopeAction`, `scope_id: str`, `target_arns: frozenset[str]`, `writer_evidence_digest: str`, `side_effect_evidence_digest: str`, `host_binding: str`, `owner_principal_id: str`, `decision_id: str`, `issued_at_utc: datetime`, `expires_at_utc: datetime`, `reason: str`. No free-form/unsigned mapping is a proof.
- `verify_scope_decision(envelope: Mapping[str, object], *, trust: OwnerTrust, action: ScopeAction, now_utc: datetime) -> VerifiedScopeDecision`: verify Owner signature against the pre-enrolled pinned Trust Anchor and a distinct purpose-bound OpenSSH namespace `aws-cost-name-tagger-scope-decision-v1`; verify role, action, canonical sorted/deduplicated ARN set, digests, scope ID, host binding, timestamps, nonce and unique decision ID. A Name/execution approval cannot stand in for a scope decision. If key enrollment, role, scope, canonical identity or evidence is unverified, fail closed (`BLOCKED_OWNER_AUTHN` or `BLOCKED_SCOPE_STATE_UNKNOWN`).
- `open_ledger(path: Path, *, trusted_host: bool) -> IntentLedger` rejects symlinks, unsafe owner/mode, unexpected host, missing historical state or torn DB. `IntentLedger.initialize_scope(decision: VerifiedScopeDecision, *, scope: ScopeEvidence, side_effects: Sequence[SideEffectEvidence]) -> None` and `release_scope(decision: VerifiedScopeDecision, *, scope: ScopeEvidence, side_effects: Sequence[SideEffectEvidence]) -> None` accept **only** purpose-verified decisions for the matching action. Recheck exact `scope.writer_control_scope_id`, Account/Partition/Region, decision.target_arns == verified controlled ARN set, complete per-ARN side-effect coverage, evidence digests, host binding, expiry and prior decision replay state; a caller-created object lacking verifier provenance is rejected.
- Preserve `create_intent(authorization: VerifiedEnvelope, *, scope_id: str) -> IntentHandle`, `consume_first_send(handle: IntentHandle) -> FirstSendPermit`, `effective_scope_state(scope_id: str) -> str`, `record_readback(handle: IntentHandle, *, name_after: str | None, outcome: str) -> None`, `hold_scope(scope_id: str, *, reason: str) -> None`. `FirstSendPermit` remains process-local, nonpersistable, single-use, bound to verified authorization/ARN/Name/scope/operation and the current exclusive execution; an `IntentHandle` or historical `SEND_ATTEMPT_CONSUMED` record alone never permits a send.
- **F006 — verifier authenticity at Intent boundary:** `create_intent(authorization: VerifiedEnvelope, *, scope_id: str)` obtains the pinned host Owner Trust Anchor from the trusted ledger/execution bootstrap (never from an untrusted caller parameter) and calls Task 1 `revalidate_verified_envelope(authorization, kind="execution", trust=protected_owner_trust, now_utc=trusted_now)` **before writing any Intent**. It rejects forged/modified `VerifiedEnvelope` instances, wrong purpose, mismatching canonical bytes/`content_id`, expired/revoked keys and mismatching scope. All persisted fields, especially `aws_operation`, and the issued `FirstSendPermit` come from the **newly revalidated immutable signed payload**, not mutable `authorization.payload` aliases or caller-supplied operation strings. Revalidation failure => `BLOCKED_OWNER_AUTHN`, Intent creation 0, Permit 0; existing old Intent/replay/HOLD rules remain unchanged.
- **F006 — AWS operation supply and permit binding:** `create_intent` accepts a **Task 1 verified execution** `VerifiedEnvelope` exclusively (namespace `aws-cost-name-tagger-execution-v1`); it must reject a Name envelope, an unverified/forged object or a mismatched `scope_id`. The ledger extracts `authorization_id = authorization.content_id`, `execution_nonce`, `resource_arn`, `approved_name`, `writer_control_scope_id` and **normalized `aws_operation`** from that *same signed execution payload*; there are no independently user-supplied ARN/Name/operation arguments. `aws_operation` is the immutable service/API/version identifier fixed by that Owner authorization (first volume target: `ec2:CreateTags:2016-11-15`); missing, malformed, noncanonical, unsupported or conflicting identifiers are rejected before Intent creation. Record this exact identifier durably with the Intent. `consume_first_send` verifies the current exclusive execution ownership and durable `SEND_ATTEMPT_CONSUMED`, then returns a nonpersistable single-use `FirstSendPermit` bound to **`authorization_id`, `resource_arn`, `approved_name`, `writer_control_scope_id`, `aws_operation` and current execution ownership**. `IntentHandle` alone, caller arguments, prior grants or an ID-only digest cannot mint or extend a Permit.
- **No implicit initialization / legal state transitions:** A missing/`UNKNOWN` scope is **not automatically eligible for `INITIALIZE`**. `IntentLedger.initialize_scope()` may durably transition a scope to `CLEARED` only when the authoritative host ledger and complete Intent/scope history are intact, the scope is provably **never registered**, no prior incomplete Intent or HOLD history exists for it (including any fixed/aliased target scope), and a verified Owner `INITIALIZE` decision and complete safety evidence match. `UNKNOWN` caused by corruption, missing/unreadable history, unsafe scope mapping or any inability to prove that the scope is new must fail closed, not be treated as a blank ledger. Existing `HOLD`, prior incomplete Intent or already-registered scopes must reject `INITIALIZE` **without scope/Intent state change or fake/live send**; do not bypass HOLD by switching scope IDs. `HOLD → CLEARED` and recovery from prior incomplete Intent require `release_scope()` with a separate verified Owner `RELEASE` decision, refreshed control/side-effect evidence and durable release audit. Neither operation resets spent authorization IDs, nonces or prior Intents. Creating an empty DB, opening the ledger or registering scope metadata cannot itself establish `CLEARED`.
- **Fixture separation:** `test_name_tag_ledger.py` may use a test-only helper to seed an explicitly marked `fixture_only` `CLEARED` scope in an isolated temporary DB; production `open_ledger` rejects fixture markers, and fixture state/signatures do not authenticate production initialization. Production `CLEARED` is never reached by passing a boolean, environment variable or CLI flag.

**Durability/security:** Secure single-host cross-process lock protects preflight, scope/Intent checks and the single authorized write invocation. SQLite rollback journal with `synchronous=FULL`, verified transaction commit, protected directory, file and host binding; never hold a DB transaction over the SDK call. On crash before a durable scope initialization/release commit, state remains non-`CLEARED` (or `UNKNOWN` if persistence integrity is unprovable). On crash after release commit, the old nonce/Intent/authorization stay consumed. Lock failure, corrupt/missing ledger, stale scope mapping or incomplete affected-scope discovery blocks writes. Preserve `CURRENT_EXECUTION_INTENT` versus `PRIOR_INCOMPLETE_INTENT` and only one new, current-execution `ALLOW_FIRST_SEND`; crash after durable `SEND_ATTEMPT_CONSUMED` never revives permission.
